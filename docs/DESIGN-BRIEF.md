# ТЗ на дизайн виджета «Распределение сделок» (amoCRM)

Документ для передачи дизайнеру. Описывает продукт, платформенные ограничения,
экраны, компоненты, текущую палитру и перечень ассетов к сдаче. Цель редизайна —
привести все поверхности к единой, аккуратной системе, сохранив совместимость с
amoCRM и брендом **KO:AGENCY**.

---

## 1. О продукте

**Что это.** Виджет для amoCRM/Kommo, который автоматически распределяет входящие
сделки между менеджерами по правилам (воронка + этап), с учётом онлайн-статуса
менеджера, рабочего графика и метода (по очереди / по загрузке).

**Кто пользователи.**
- **Администратор/РОП** — настраивает правила, графики, состав участников
  (основной объём экранов).
- **Менеджер** — иногда переключает свой статус «в распределении / вне».

**Бренд.** KO:AGENCY. Акцент — фирменный красный. Тон — деловой, чистый,
без «игрушечности». Ближайший ориентир по плотности/строгости — сам интерфейс
amoCRM, но с узнаваемым акцентом бренда.

---

## 2. Платформенные ограничения (обязательно к соблюдению)

Виджет живёт **внутри amoCRM**, это накладывает жёсткие рамки — дизайн должен их
учитывать, иначе он нереализуем:

1. **Встраивание.** Интерфейс рендерится внутри страниц amoCRM (не полноэкранное
   приложение). Нельзя опираться на фиксированные размеры окна; ширина резиновая.
2. **Ширина контента.** Полностраничный экран центрируется, **макс. ширина ≈ 1080 px**;
   на узких — перестроение в 1 колонку (брейкпоинт ~760 px).
3. **Тема amoCRM.** У amoCRM есть светлая и **тёмная** темы. Сейчас виджет —
   светлый. Нужно решить: (а) сделать дизайн-токены под обе темы, или
   (б) осознанно остаться light-only. **Требуется вариант для тёмной темы или явное
   обоснование отказа** (см. §9, вопрос 1).
4. **Локализация.** Все тексты — через словари **RU/EN**. Никаких «зашитых» строк
   в макете как единственного варианта; для длинных строк (немецкий/русский длиннее
   английского) закладывать запас по ширине, кнопки не должны ломаться.
5. **Самодостаточные ассеты.** Внешние CDN/шрифты недоступны. Иконки — инлайн-SVG
   или спрайт в архиве; шрифт — системный стек (см. §6). Кастомный шрифт = отдельный
   разговор (вес файла в архиве).
6. **Не ломать layout amoCRM.** Виджет не перекрывает нативные панели; длинные
   списки скроллятся **внутри своего контейнера**, а не растягивают страницу
   (реальная бага, которую чинили: ростер сотрудников «уезжал» за экран).
7. **Плотность.** Это рабочий инструмент с таблицами и списками на десятки строк —
   приоритет читаемости и компактности над крупными «маркетинговыми» блоками.

## 3. Экраны (поверхности), которые нужно оформить

| # | Экран | Где показывается | Приоритет |
|---|---|---|---|
| S1 | **Полностраничный интерфейс** (сайдбар + рабочая область) | `advanced_settings` и левое меню (публичная сборка) | 🔴 главный |
| S2 | **Панель настроек с вкладками**: Сотрудники · Правила · Расписания · История | окно настроек виджета | 🔴 главный |
| S3 | **Модальное окно** (шаблон/правило/подтверждения) | поверх S1/S2 | 🟠 |
| S4 | **Экран установки/авторизации** (OAuth) | popup при установке | 🟡 |
| S5 | **Панель Digital Pipeline** (менеджеры для этапа) | редактор Digital Pipeline amoCRM | 🟡 |
| S6 | **Пункт левого меню** (иконка + подпись «Распределение») | левый навбар amoCRM (публичная) | 🟡 |

### S1 — Полностраничный интерфейс (главный)
- **Сайдбар** (~236 px): логотип-марка KO:AGENCY, блок «ONLINE» с личным
  тумблером участия, навигация (Статусы, Шаблоны, + пункты «Рабочее время»,
  «Отчёты» со статусом «скоро»/disabled), футер с адресом сервиса.
- **Рабочая область**: заголовок раздела + описание, карточки/таблицы.
- Раздел **«Статусы»**: счётчик «Участвуют: N из M», кнопка «Обновить», таблица
  сотрудников (аватар с инициалами, имя, группа-разделитель, тумблер справа).
- Раздел **«Шаблоны»**: таблица шаблонов (название, тип-бейдж, число менеджеров,
  действия ✎/×), кнопка «+ Добавить».

### S2 — Панель настроек с вкладками
- Табы: **Сотрудники / Правила / Расписания / История**.
- «Правила»: поле URL сервера, селект метода, список карточек-правил.
  Карточка правила: **Воронка + Этап** (2 селекта), список **ответственных
  менеджеров** (добавляемые строки), чекбоксы «учитывать историю» /
  «учитывать расписание», сворачиваемая секция **«Фильтры сделок»** (бюджет от/до,
  название содержит, теги, доп. поля с операторами).
- «Расписания»: по менеджеру — таймзона и часы по дням недели (вкл/выходной).
- «История»: журнал распределений (таблица).

### S4 — Экран установки (OAuth)
Простой центрированный экран подтверждения: марка KO:AGENCY + короткий текст
(«Установка завершена» / «Авторизация успешна» / «повторите авторизацию»).
Нужен аккуратный минимальный шаблон (успех / нейтральное сообщение).

### S6 — Иконка левого меню
Монохромная SVG-иконка (сейчас `menu_light.svg` / `menu_dark.svg`, 437 б каждая),
хорошо читается в **16–24 px**, отдельные версии под светлый и тёмный навбар.

## 4. Инвентарь компонентов (единая система)

Спроектировать как переиспользуемый набор, консистентный на всех экранах:

- **Кнопки:** primary (акцент), secondary (контур), danger, icon-button, размер sm;
  состояния: hover / active / disabled / loading («Сохраняется…»).
- **Переключатель (toggle):** вкл/выкл; в рабочей области вкл = акцентный, в сайдбаре
  вкл = зелёный (online). Размер трека ~38×22, ясно читаемое состояние.
- **Поля ввода:** text, password (секретный ключ), number, select; фокус, ошибка,
  подсказка (hint), метка с признаком «обязательно».
- **Таблицы/списки:** заголовок (uppercase, приглушённый), строки с разделителями,
  групп-разделитель (напр. «GROUP_0»), липкий заголовок при скролле, зебра не
  обязательна. Длинные списки — скролл внутри карточки (`max-height`).
- **Аватар:** круг с инициалами, палитра из 7 цветов (детерминированно по ID).
- **Чипы** (выбранные менеджеры) с крестиком; для «процентного» метода — поле %.
- **Бейджи/теги:** тип шаблона, статусы (success/muted).
- **Табы** (S2) и **вертикальная навигация** (S1), активное/hover/disabled+«скоро».
- **Модалка:** шапка с заголовком и ×, тело со скроллом, футер с кнопками
  (Отмена/Сохранить). Ширина ~520 px, `max-height 90vh`.
- **Тосты/уведомления:** используется нативный механизм amoCRM (success/error/info)
  — задать тон текста, не кастомный визуал (визуал не наш).
- **Пустые и ошибочные состояния:** иконка-кружок + текст (нет данных / ошибка
  загрузки). Нужны аккуратные иллюстративные заглушки (лёгкие, не тяжёлые).
- **Индикатор загрузки:** текст/скелетон для таблиц.

## 5. Текущая палитра (отправная точка — можно улучшать, но зафиксировать токенами)

| Роль | Значение | Где |
|---|---|---|
| Акцент (бренд) | `#d22730` | primary-кнопки, активный таб/навпункт, вкл-тумблер (main) |
| Акцент-2 (лого) | `#e5484d` | точки в марке лого |
| Online (зелёный) | `#25c26e` | тумблер online в сайдбаре, точка-статус |
| Текст основной | `#141414` | заголовки, значения |
| Текст вторичный | `#586173` | описания, подписи |
| Текст приглушённый | `#8b95a7` / `#98a1b3` | hint, заголовки таблиц |
| Фон карточек | `#ffffff` | карточки, поля |
| Фон сайдбара/зон | `#fafbfc` / `#f6f8fc` | сайдбар, шапки таблиц |
| Границы | `#e4e9f1` / `#eef2f8` / `#dde3ec` | разделители, обводки |
| Danger-фон | `#fdebec` / `#fde8e8` | ошибки/удаление |

**Скругления:** мелкие 6–7 px (поля/кнопки), карточки 10–14 px, круглые 50 %,
пилюли 999 px. **Тени** — мягкие, низкая непрозрачность (напр. `0 8px 26px rgba(30,41,73,.10)`).

> Дизайнеру: палитру можно эволюционировать (в т.ч. под тёмную тему), но результат
> сдать **набором дизайн-токенов** (цвета, радиусы, тени, отступы, типографика),
> чтобы мы перенесли их в CSS-переменные 1:1.

## 6. Типографика

- Системный стек: **`"Roboto", "Arial", sans-serif`** (Roboto — родной для amoCRM),
  моно — `'Roboto Mono', ui-monospace, monospace` (числа/счётчики).
- Размеры сейчас: заголовки разделов ~18 px/700, тело 13 px, подписи 11–12.5 px,
  заголовки таблиц 10.5 px uppercase. Задать полноценную шкалу (H1–H4, body, caption,
  mono) с line-height.
- Если предлагается кастомный шрифт — обосновать и учесть вес в архиве (см. §2.5).

## 7. Ассеты к сдаче

- **Логотип KO:AGENCY** — варианты, аналогичные текущим: `logo`, `logo_medium`,
  `logo_main`, `logo_min`, `logo_small`, `logo_dp` (для Digital Pipeline). Форматы
  PNG (ретина ×2) + желательно исходный SVG.
- **Иконка левого меню** — `menu_light.svg`, `menu_dark.svg` (монохром, 16–24 px).
- **Обложка маркетплейса** — `cover.jpg` (для карточки в amoМаркете; уточнить
  требования размера у amo).
- **Иконки интерфейса** — набор инлайн-SVG (обновить/edit/delete/×/стрелки/чекбокс/
  аватар-плейсхолдер) в едином стиле и штрихе.
- **Favicon** страницы установки (опц.).
- **Дизайн-токены** — JSON или таблица (см. §5).

## 8. Состояния и взаимодействия (обязательно показать в макете)

- Тумблер: вкл / выкл + микрофидбек «Сохранено» (тост).
- Таблицы: загрузка (скелетон) / есть данные / пусто / ошибка загрузки.
- Кнопки: hover / active / disabled / loading.
- Правило: свёрнутые/развёрнутые «Фильтры сделок».
- Навигация: активный / hover / disabled со значком «скоро».
- Скролл длинного ростера внутри карточки (липкая шапка таблицы).
- Модалка: открытие/закрытие, валидация обязательных полей.

## 9. Открытые вопросы к дизайнеру (ответить до старта)

1. **Тёмная тема amoCRM** — делаем токены под обе темы или остаёмся light-only?
   (Влияет на объём работы и на иконки левого меню.)
2. **Глубина редизайна** — косметика поверх текущей структуры или переработка
   layout (напр. другой принцип навигации в S1)?
3. **Кастомный шрифт** — оставляем системный Roboto или тянем свой (вес архива)?
4. **Иллюстрации пустых состояний** — минимал (иконки) или полноценные иллюстрации?

## 10. Формат сдачи

- **Figma**: экраны S1–S6 в состояниях (§8), библиотека компонентов (§4),
  стили/переменные (§5–§6), адаптив (десктоп + узкая колонка ~760 px).
- **Redlines/спеки** по отступам и токенам (или auto-layout + переменные Figma).
- **Экспорт ассетов** (§7) в оговорённых форматах.
- **Дизайн-токены** отдельным файлом для переноса в CSS-переменные.
