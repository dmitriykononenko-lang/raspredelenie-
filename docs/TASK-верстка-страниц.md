# Задание на вёрстку: экраны виджета «Распределение сделок»

**Тип исполнителя:** верстальщик / фронтенд-агент.
**Цель:** сверстать экраны виджета (HTML + CSS) по прототипу и дизайн-системе,
с классами, готовыми к подключению в `widget.js`. Никакой бизнес-логики — только
разметка, стили и статичные состояния.

**Что уже есть (опираться на это):**
- Прототип экранов: `docs/PROTOTYPE-экраны.md` (вайрфреймы, состояния).
- Рабочие стили: `css/widget.css` (сайдбар, таблица, тумблеры, модалка, чипы,
  сегменты, бейджи, состояния) — **переиспользовать и расширять**, не плодить дубли.
- Живой пример экрана «Шаблоны»: превью из реального `widget.css`.

---

## 1. Дизайн-система (обязательно соблюдать)

| Токен | Значение |
|---|---|
| Акцент (бренд) | **`#d22730`** · hover `#b31f27` · soft `#fdebec` |
| Тёмный (сайдбар) | `#141414` (доп. `#0E121B`) |
| Успех / варнинг | `#12915a` / `#c47812` |
| Ошибка / danger | `#d22730` (или `#fb3748`) |
| Текст | `#141414` / втор. `#586173` / приглуш. `#98a1af` |
| Границы / фон-панели | `#e6e9ee` `#e4e9f1` / `#f5f6f8` `#eef1f4` |
| Шрифт | **Roboto**; числа/даты — **Roboto Mono** (`.dist-mono`) |
| Радиусы | 7 / 9 / 12 / 14 px · тумблер-пилюля |
| Логотип | эмблема KO:AGENCY (чёрный фон, красные узлы) — inline SVG из `widget.js` |

**Именование классов — префикс `dist-`** (совпадает с кодом): `dist-page`,
`dist-side`, `dist-nav__i`, `dist-main`, `dist-card`, `dist-table`, `dist-switch`,
`dist-av`, `dist-chip`, `dist-seg`, `dist-modal`, `dist-badge`, `dist-empty-box`,
`dist-btn` (`--primary/--secondary/--danger`). Интерактивные узлы для JS помечать
классом `js-*` (например `js-tpl-add`) — по разметке из `widget.js`.

---

## 2. Ограничения (важно — это встраивается в amoCRM)

- **Без фреймворков** (React/Vue/Tailwind) и **без сборки** — чистые HTML+CSS.
- **Без внешних CDN** (шрифты/скрипты) — amoCRM отдаёт Roboto сам; для Mono
  фолбэк `'Roboto Mono', ui-monospace, monospace`.
- Верстать под **светлую** тему (amoCRM светлый); сайдбар — тёмный (бренд).
- Ширины: полная страница ≈ **1080px** (адаптив ≤760px → сайдбар сверху);
  модалка настроек ≈ **600px**; панель Digital Pipeline ≈ **380px**.
- Все динамические значения в реальном коде экранируются — в вёрстке просто
  оставляй плейсхолдеры-тексты («Анна Иванова», «#67890»).

## 3. Экраны к вёрстке (по приоритету)

Каркас (единый): `dist-page` = `dist-side` (сайдбар) + `dist-main` (контент).
Сайдбар одинаков на всех экранах; меняется только правая часть (`.js-panel`).

| # | Экран | Ключевые блоки | Статус |
|---|---|---|---|
| — | **Каркас** сайдбар+контент | лого, тумблер ONLINE, навигация, футер | ✅ есть |
| 1 | **Статусы** | таблица менеджеров (группы-отделы) + тумблеры | ✅ есть |
| 2 | **Шаблоны** + модалка | таблица (Название/Тип-бейдж/Менеджеры/действия); модалка (название, сегмент типа, чип-менеджеры, %-поля, чекбоксы) | ✅ есть |
| 3 | **Дашборд** | 4 KPI-плитки + столбчатый график по менеджерам | нужно |
| 4 | **Рабочее время** + модалка | сетка сотрудники×дни (рабочий/выходной), переключатель месяца; модалка-календарь + время с/по + «динамичный график» | нужно |
| 5 | **Отчёты** (3 таба) | фильтры + таблица (Распределения / Статусы / Заместители) | нужно |
| 6 | **Настройки** | Server URL, Security key (password), метод, индикатор связи, уведомления | нужно |
| 7 | **Оплата** (опц.) | тариф/цена, демо-режим, «Оплатить онлайн», «Запросить счёт» | нужно |
| 8 | **Digital Pipeline** (380px) | менеджеры-чипы + 2 чекбокса | ✅ есть |
| 9 | **Правила** (модалка 600px) | карточки правил (воронка→этап→менеджеры→фильтры) | ✅ есть |

Приоритет новых: **Дашборд → Рабочее время → Отчёты → Настройки → Оплата.**

## 4. Состояния (сверстать для каждого экрана-списка)

- **Загрузка** — скелетоны строк/плиток (или `.dist-muted` «Загрузка…»).
- **Пусто** — `.dist-empty-box` (иконка + текст + при необходимости CTA).
- **Ошибка** — `.dist-empty-box--err` с реальной причиной
  («Сервер недоступен. Проверьте Server URL в Настройках»).
- **Сохранение** — кнопка → «Сохраняется…», disabled.

---

## 5. Библиотека компонентов (собрать/переиспользовать)

Аватар-инициалы (`dist-av`, `--sm`), тумблер (`dist-switch`), бейдж-тип
(`dist-badge`), статус-пилюля (● Включён/Выключен), KPI-плитка, строка таблицы +
групп-заголовок отдела (`dist-tr-group`), чип-менеджер с ✕ (`dist-chip`, `__pct`,
`__x`), сегмент-переключатель (`dist-seg`), кнопки (`dist-btn --primary/…`),
иконка-действие (`dist-icon-btn`), модалка (`dist-modal__box/head/body/foot/x`),
пункт сайдбара (`dist-nav__i`, `--on`), пустое/ошибка (`dist-empty-box`).

---

## 6. Формат сдачи

- Один HTML-файл на экран **или** один файл со всеми экранами через якоря/секции —
  как удобно, но каждый экран самодостаточно рендерится в браузере.
- Стили — в общий CSS в стиле `widget.css` (те же классы). Новые компоненты
  дописывать в конец, с комментарием-разделителем.
- **Критерий приёмки:** экран визуально совпадает с прототипом и дизайн-системой,
  открывается в браузере без ошибок консоли, адаптивен до 760px, классы `dist-*`
  и `js-*` соответствуют разметке из `widget.js` (чтобы подключение было 1:1).

## 7. Чего НЕ делать

- Не подключать внешние шрифты/скрипты/CDN.
- Не менять фирменные цвета (акцент только `#d22730`).
- Не добавлять бизнес-логику/AJAX — только разметка и статичные состояния.
- Не переименовывать существующие классы `dist-*` (сломается привязка к коду).
