# Установка приватной интеграции «Распределение сделок» в аккаунт КЛИЕНТА (amoCRM)

Пошаговая инструкция по установке виджета в **аккаунт клиента**. Приватная
интеграция ставится в один аккаунт, авторизация — по **долгоживущему токену**
(для приватной он доступен, в отличие от публичной). Левого меню у приватной
нет — интерфейс открывается со страницы интеграции (раздел «Настроить»).

Ориентировочное время — 15–20 минут.

## Роли: кто что делает

| Шаг | Где | Кто |
|---|---|---|
| §1–§3 создать интеграцию, загрузить архив, установить, **сгенерировать токен** | в кабинете **клиента** (amoCRM) | админ клиента **или** вы с доступом к аккаунту клиента |
| §4 вписать токен в `.env`, перезапустить | на **сервере KO:AGENCY** (`/opt/raspredelenie`) | вы (KO:AGENCY) — у клиента доступа к серверу нет |
| §5–§6 настроить сотрудников/правила, включить срабатывание | в кабинете клиента | вы вместе с клиентом |

> **Клиент передаёт вам 3 значения** из §3: долгоживущий токен, ID аккаунта и
> поддомен (`xxx.amocrm.ru`). Токен — секрет: передавать защищённым каналом, не
> в открытом чате.

> ⚠️ **Один клиент на текущую конфигурацию сервера.** Backend сейчас хранит один
> долгоживущий токен в `.env` (`AMO_ACCOUNT_ID` привязывает его к конкретному
> аккаунту). Для нескольких клиентов на одном сервере нужен мультиаккаунт-режим
> (OAuth-установка на каждый аккаунт) — отдельная доработка.

---

## 0. Что нужно заранее

- **Архив виджета**: `deal-distribution-widget-v1.1.0.zip` (приватная сборка).
- **Backend поднят и отвечает**: открой в браузере
  `https://raspredelenie.koagency.ru/health` → должно вернуть
  `{"status":"ok","service":"deal-distribution"}`.
  Если нет — сначала разверни сервер (`docs/DEPLOY-SHARED.md`).
- **Права администратора** в amoCRM.

---

## 1. Создать приватную интеграцию и загрузить архив

1. amoCRM → **Настройки → Интеграции** → **«+ Создать интеграцию»** →
   **приватная** («Загрузить свою интеграцию»).
2. Заполни Redirect URI и права (см. §2), сохрани — интеграция создастся.
3. Открой вкладку **«Ключи и доступы»** и скопируй **«Код виджета»** и
   **«Секретный ключ»** этой интеграции.
4. **Собери архив С ЭТИМИ значениями** (amoCRM требует `code`+`secret_key` в
   архиве даже для приватной — иначе «widget not found» / «Secret key not
   correct» и статус «Отключено»):
   ```bash
   cd /opt/raspredelenie
   AMO_WIDGET_CODE=<Код виджета> AMO_CLIENT_SECRET=<Секретный ключ> ./build.sh
   # → dist/deal-distribution-widget-v1.1.0.zip (с вшитыми code/secret)
   ```
   > Секрет берётся из окружения и в git не попадает. Без этих переменных
   > `./build.sh` соберёт архив БЕЗ code/secret и предупредит — такой не
   > установится.
5. Загрузи получившийся `dist/deal-distribution-widget-v1.1.0.zip` в эту же
   интеграцию (кнопка загрузки/обновления архива).

> Если архив не принимается или установка «слетает» в «Отключено» — см. §7.

---

## 2. Указать Redirect URI и права

В карточке интеграции → **«Настроить»** (или «Редактировать»):

1. **Redirect URI** — ровно, буква-в-букву:
   ```
   https://raspredelenie.koagency.ru/oauth/callback
   ```
   ⚠️ `https`, без слэша в конце. Любое расхождение → ошибка при установке.
2. **Права доступа**: доступ к **сделкам** и **пользователям** (минимум).
3. Сохранить.

---

## 3. Установить и получить долгоживущий токен

1. Нажми **«Установить»**. Виджет должен перейти в статус **«Активно»**.
   (В режиме долгоживущего токена бэкенд просто подтверждает установку.)
2. Открой вкладку **«Ключи и доступы»**.
3. Нажми **«Сгенерировать долгоживущий токен»** — для **приватной** интеграции
   кнопка работает (для публичной была ошибка «Current client is not private or
   external»). Срок — максимальный.
4. **Скопируй и передай в KO:AGENCY** (защищённым каналом) три значения:
   - **долгоживущий токен** (показывается один раз — сразу сохрани);
   - **ID аккаунта** — числовой, например `33022710` (виден в URL аккаунта или в
     «Настройки → (о аккаунте)»);
   - **поддомен** аккаунта — `xxx.amocrm.ru`.

   Эти значения нужны для §4 (их вписывают на сервере KO:AGENCY). У клиента
   доступа к серверу нет — дальше §4 выполняет KO:AGENCY.

---

## 4. Прописать токен на сервере (`server/.env`)

На сервере (`/opt/raspredelenie/server/.env`) заполни приватный режим:

```env
# Приватный режим: авторизация по долгоживущему токену
AMO_LONG_TERM_TOKEN=<вставь долгоживущий токен>
AMO_ACCOUNT_ID=<ID аккаунта, напр. 33022710>
AMO_BASE_DOMAIN=<subdomain>.amocrm.ru

# OAuth-поля для приватного режима НЕ нужны — оставь пустыми
AMO_CLIENT_ID=
AMO_CLIENT_SECRET=
AMO_REDIRECT_URI=https://raspredelenie.koagency.ru/oauth/callback
```

Применить (перечитывает `.env` без пересборки):
```bash
cd /opt/raspredelenie
docker compose -p raspredelenie -f docker-compose.shared.yml restart app
```

> **Безопасность:** токен вписывается ТОЛЬКО в `.env` на сервере, в git не
> коммитится. Если токен где-то засветился — перегенерируй его в кабинете и
> обнови `.env`.

## 5. Открыть виджет и задать настройки

Со страницы интеграции открой рабочую область виджета (кнопка **«Настроить»** →
раздел «Распределение»). Увидишь сайдбар: **Статусы · Отчёты · Настройки**.

### 5.1. Сотрудники (кто участвует)
Раздел **«Статусы»**: включи тумблеры менеджерам, которые должны получать сделки.
По умолчанию все включены; выключенный сделок не получает. Переключение
сохраняется сразу (появляется тост «Сохранено»).

### 5.2. Правила / Шаблоны
Раздел **«Настройки → Шаблоны»** → **«+ Новый шаблон»**:
- **Название** шаблона;
- **Алгоритм**: «По очереди» (round-robin) или «По нагрузке»;
- **Участники**: выбери менеджеров;
- при желании — доп. опции (учитывать историю/график).
Сохрани. Правила проверяются сверху вниз — первый подходящий назначает
ответственного.

### 5.3. URL сервера
Если в настройках виджета есть поле **Server URL** — впиши
`https://raspredelenie.koagency.ru` (в сборке адрес уже вшит по умолчанию, поле —
необязательное переопределение).

---

## 6. Включить срабатывание распределения

Чтобы сделки распределялись автоматически, нужно, чтобы amoCRM дёргал вебхук при
попадании сделки на этап:

- **Digital Pipeline**: на нужном этапе воронки добавь действие виджета
  «Распределение» (вебхук уходит на `https://raspredelenie.koagency.ru/webhook/leads`).

Проверка вручную (без движения сделки) — см. `docs/CONFIGURE-VIA-API.md`
(`POST /api/distribute`).

После срабатывания результат виден в разделе **«Отчёт по распределениям»**.

## 7. Если что-то пошло не так

| Симптом | Причина / решение |
|---|---|
| Архив не загружается | Проверь, что это приватная сборка (`deal-distribution-widget-v1.1.0.zip`), `manifest.json` в корне архива. |
| После установки статус «Отключено» | Бэкенд не подтвердил установку. Проверь `/health` и логи: `docker compose -p raspredelenie -f docker-compose.shared.yml logs --tail=80`. Redirect URI должен точно совпадать (§2). |
| Кнопка долгоживущего токена: «Current client is not private or external» | Интеграция создана как **публичная**. Долгоживущий токен только для приватной — пересоздай как приватную. |
| Списки сотрудников/расписаний не грузятся | Бэкенд недоступен или `.env` не применился. `restart app`, проверь `/health`, консоль браузера (F12 → Network → `/api/status`). |
| Правки `.env` «не видны» | Убедись, что делаешь `restart app` (в compose `env_file` убран, файл читается напрямую). Детали — `TROUBLESHOOTING.md` §5. |
| Сделки не меняют ответственного | Нет подходящего правила (§5.2) или все участники выключены (§5.1). Проверь «Отчёт по распределениям». Токен действителен? (401 в логах = токен недействителен/не для этого аккаунта.) |
